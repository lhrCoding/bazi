# calendar.md —— 排盘约定（历法、节气、子时、真太阳时、闰月、大运）

> 版本：v2（2026-10-29，mingli-expert）
> v2 变更：子时口径由“23:00 换日”改为用户选定的**早晚子时派**（见 §3.3）；真太阳时“未选出生地 = 不校正 + 标注「未校正」”写成硬性要求（§4）。
> 适用：P0-2「精确排盘」。本文件只规定**怎么排**，不涉及旺衰喜忌（见 strength.md / yongshen.md）。
> 规则编号以 `CAL-` 开头，代码输出「触发规则」时引用这些编号。

---

## 0. 总流程（判定顺序）

```
输入（公历/农历、日期、时间或“不知道时辰”、性别、出生地[可选]）
 ① CAL-INPUT   农历 → 公历（处理闰月）
 ② CAL-TZ      本地钟表时间 → UTC（用 IANA 时区库，自动处理 1986–1991 夏令时）
 ③ CAL-YM      年柱、月柱：用“出生的绝对时刻（UTC）”与“节气的绝对时刻”比较
 ④ CAL-TST     若选了出生地：UTC + 经度 + 均时差 → 真太阳时；否则用北京时间（UTC+8 标准时），标记 tst_status = "未校正"
 ⑤ CAL-DH      日柱、时柱：用第④步得到的“当地时间”，日柱按 24:00（午夜）换日；23:00–24:00 为晚子时，时干按次日日干起
 ⑥ CAL-YUN     大运：顺逆 + 起运（用绝对时刻到相邻“节”的分钟数）
 ⑦ 输出：四柱、每柱藏干、十神、触发的 CAL 规则编号、(若有) 不确定性标记
```

---

## 1. 年柱：以立春为界（CAL-YM-1）

- 干支年从**立春交节时刻**开始，不是公历 1 月 1 日，也不是农历正月初一（春节）。
- 出处：《渊海子平》《三命通会》均以节气定年月，子平法通行做法。
- 典型陷阱：
  - 公历 1 月、2 月初出生 → 很可能还是上一个干支年（案例 C16：1994-01-09 → 癸酉年）。
  - 春节后、立春前出生 → 农历已是新年，但干支年**仍是旧年**（案例 C03：2023-01-28，农历癸卯年正月初七，年柱却是壬寅）。
  - 立春当天，以交节的**时、分**为界（案例 C01 / C02）。

## 2. 月柱：以“十二节”为界（CAL-YM-2）

只有 12 个“节”换月，12 个“中气”（雨水、春分……）不换月。

| 月支 | 起始的节 | 太阳视黄经 |
|---|---|---|
| 寅 | 立春 | 315° |
| 卯 | 惊蛰 | 345° |
| 辰 | 清明 | 15° |
| 巳 | 立夏 | 45° |
| 午 | 芒种 | 75° |
| 未 | 小暑 | 105° |
| 申 | 立秋 | 135° |
| 酉 | 白露 | 165° |
| 戌 | 寒露 | 195° |
| 亥 | 立冬 | 225° |
| 子 | 大雪 | 255° |
| 丑 | 小寒 | 285° |

- 月干用“五虎遁”：甲己年丙寅月起，乙庚年戊寅，丙辛年庚寅，丁壬年壬寅，戊癸年甲寅。
- 节气时刻要求**精确到分钟**（PRD P0-2）。推荐实现：寿星天文历算法（lunar-javascript / lunar-python / sxtwl 均基于它），本项目核对时与 VSOP87（PyEphem）独立计算结果相差 < 15 秒。
- **比较方式（重要）**：节气是天文上的绝对时刻。年柱、月柱用“出生的绝对时刻”和“节气的绝对时刻”比较（都换成 UTC 或都换成北京标准时间比），**不用真太阳时去比节气**。
  - 理由：真太阳时只是“当地太阳在天上的位置”，用于定日、时；节气是全球同一时刻发生的事件。部分 App 用真太阳时比节气，会在交节附近错一个月，本项目不采用。

## 3. 日柱、时柱（CAL-DH）

### 3.1 日柱
- 日柱按 60 甲子连续循环，与历法无关（参考点：2000-01-01 为戊午日，可做单元测试）。
- 使用的“日期”是 CAL-TST 得到的当地时间（选了出生地 = 真太阳时；没选 = 北京时间）。

### 3.2 时柱
- 十二时辰：子 23:00–00:59，丑 01:00–02:59，……，亥 21:00–22:59（左闭右开，23:00:00 算子时）。
- 时干用“五鼠遁”：甲己日甲子时起，乙庚日丙子，丙辛日戊子，丁壬日庚子，戊癸日壬子。

### 3.3 子时处理（CAL-DH-ZI）——有争议，用户已拍板：早晚子时派（2026-10-29）
| 流派 | 23:00–23:59 出生的日柱 | 23:00–23:59 的时柱 | 00:00–00:59 |
|---|---|---|---|
| **B. 早晚子时派（本项目采用）** | 仍算**当日**（日柱 24:00 才换） | 子时，时干按**次日**日干五鼠遁起（= 当日子时干 + 2） | 早子时：当日日柱，时干按当日日干起 |
| A. 23:00 换日派（不采用，仅留作对照） | 算**次日** | 子时，时干按次日日干起 | 同左 |

- 两派的**时柱完全相同**，只有 23:00–23:59 的**日柱**不同。
- 举例（案例 C05）：1995-03-15 乙巳日 23:30 → 日柱**乙巳**（当日），时柱**戊子**（按次日丙午的“丙辛日戊子时”起）；同一天 00:30 → 乙巳日**丙子**时（按当日乙的“乙庚日丙子时”起，案例 C04）。
- 关于“晚子时的时干用哪天起”：主流晚子时派（也是 lunar 库 sect=2 的实现）用**次日**日干起，本项目照此执行。少数书另有“晚子时时干仍按当日日干起（乙巳日 23:30 → 丙子时）”的说法，本项目**不采用**，理由：那样会让一天出现两个完全相同的“丙子时”，而按天时连续性，23:00 起的这个子时与次日 00:00 的子时是同一个时辰，干支理应连续。
- 选择理由（用户决定，记录如下）：民间排盘软件与多数现代命理书默认此派，用户对照外部 App 时结果一致，可减少“你们排错了”的客诉。
- 代码同时算出 A 派日柱，放在 `alt.zi_huanri_day_pillar` 字段（结果页不显示，测试校验，便于将来切换）。
- **对照库**：lunar-python / lunar-javascript 的 `EightChar.setSect(2)` = 本项目采用的 B 派（日柱当日、时干按次日起）；`setSect(1)` = A 派。sect=2 在已知版本里是库的**默认值**，但默认值可能随版本变化——**开发必须显式调用 `setSect(2)`，并加一条单元测试（C05）确认库的实际行为**，不要依赖默认值。
- 与真太阳时的关系：判断“是否 23:00–24:00 / 是否跨午夜”一律用 CAL-TST 得到的当地时间（选了出生地 = 真太阳时）。例如北京时间 00:10、真太阳时校正为前一日 23:40 → 日柱取**前一日**、时柱为子时（时干按北京日期那一天的日干起）。

## 4. 真太阳时（CAL-TST）

**硬性规则（用户 2026-10-29 确认）**：
- 只有用户**主动选了出生地**才做真太阳时校正，输出 `tst_status = "已校正"`。
- 没选出生地：直接用北京时间（准确说是 CAL-TZ 换算出的 UTC+8 标准时），**不做任何校正、不猜测出生地**（不按 IP、不按手机号归属地），输出 `tst_status = "未校正"`。
- `tst_status = "未校正"` 时，免费结果页四柱下方、付费报告第 0 章都必须显示一行灰字：“时辰按北京时间排定，未做真太阳时校正。如出生地离东经 120° 较远，时柱可能不同，可补充出生地重新排盘。”
- 未校正时若出生时刻离时辰边界（奇数整点）不足 30 分钟，再加一句：“你的出生时间接近时辰交界，补充出生地后时柱可能变化。”（仅提示，不改变排盘。）

```
UTC        = 本地钟表时间按 IANA 时区（默认 Asia/Shanghai）换算
平太阳时   = UTC + 经度 × 4 分钟            （东经为正）
真太阳时   = 平太阳时 + 均时差 EoT(UTC)
```

均时差（分钟）用 NOAA 近似式即可（误差 < 1 分钟）：
```
g   = 2π/365 × (年内第几天 − 1 + (UTC小时 − 12)/24)
EoT = 229.18 × (0.000075 + 0.001868·cos g − 0.032077·sin g
                − 0.014615·cos 2g − 0.040849·sin 2g)
```
- 均时差全年在 −14.2 ～ +16.4 分钟之间（2 月中最负，11 月初最正）。
- 出生地 → 经度：用城市/区县经纬度表（精确到 0.01°）；不需要纬度。
- 真太阳时**只影响日柱和时柱**（见 CAL-YM-2 的比较方式）。
- 校正后若跨过 00:00（午夜），日柱随之变化；跨过 23:00 只改变时柱、不改变日柱（早晚子时派）。案例 C08：乌鲁木齐北京时间 00:40 → 真太阳时前一日 22:19，跨过了午夜，日柱、时柱都变。
- 结果页要显示：“北京时间 xx:xx → 真太阳时 xx:xx（经度修正 ±x 分、均时差 ±x 分）”，让用户看得懂为什么时辰变了。

## 5. 时区与夏令时（CAL-TZ）

- 一律用 IANA 时区库（Python `zoneinfo`、JS `Intl`/`luxon`）把“出生证上的钟表时间”换成 UTC，**不要手写 +8**。
- 中国大陆 1986–1991 年实行夏令时，夏令时期间钟表比标准时间快 1 小时。IANA `Asia/Shanghai` 已内置（核对输出）：

| 年 | 夏令时开始（当地钟表） | 结束 |
|---|---|---|
| 1986 | 05-04 02:00 → 03:00 | 09-14 02:00 → 01:00 |
| 1987 | 04-12 | 09-13 |
| 1988 | 04-17（另有资料作 04-10，以 tzdata 为准） | 09-11 |
| 1989 | 04-16 | 09-17 |
| 1990 | 04-15 | 09-16 |
| 1991 | 04-14 | 09-15 |

  1949 年以前也有零星夏令时，tzdata 同样覆盖。
- 夏令时结束那天 01:00–01:59 出现两次（重复时刻），默认按**标准时间**（较晚的那次，`fold=1`）解释，并在结果页提示。夏令时开始那天 02:00–02:59 不存在，表单提示“该时刻不存在，请核对”。
- 海外出生：用户选国家/城市 → 对应 IANA 时区 → UTC，后续同上；节气比较仍用绝对时刻，没有任何特殊处理。
- 新疆用户：出生证一般记北京时间，但也有人习惯说“新疆时间”（UTC+6）。表单在选了新疆城市时提示“请填北京时间”。

## 6. 农历输入与闰月（CAL-INPUT）

- 农历只用于**输入**：先换成公历，之后所有计算与公历输入完全相同。四柱与农历月份无关。
- 闰月：表单在用户选的年份有闰月时，月份下拉里出现“闰X月”；没有闰月的年份不出现。转换用 lunar 库（`Lunar.fromYmdHms(y, -m, d, ...)` 负数月 = 闰月）。
- **闰月不等于某个月柱**：月柱只看节气（案例 C07：农历闰二月十五 08:30 在清明 09:13 之前 → 月柱乙卯；同一天 10:00 以后就是丙辰）。
- 非法日期（如农历小月三十、不存在的闰月）在表单阶段拦截。

## 7. 不知道时辰（CAL-NOHOUR）

- 只排年、月、日三柱；时柱、时干支藏干、时柱十神全部为空。
- 日柱按用户填的日期（早晚子时派下 23:00 本来也不换日，无需特殊处理）。
- 12 时辰扫描（strength.md S-NOHOUR）共扫 **13 个时柱**：早子（00:00–00:59，按当日日干起）、丑……亥、晚子（23:00–23:59，按次日日干起）。
- 若出生日当天有“节”交接（即当天可能跨月，立春当天还可能跨年）：
  - 以当天 12:00（北京时间）为默认计算；
  - 输出 `uncertain.month_pillar = [交节前的年月柱, 交节后的年月柱]` 和交节时刻，结果页提示“您出生当天 HH:MM 交节，若知道出生在此之前或之后，结果会更准”（案例 C19）。
- 大运起运时间按 12:00 计算，误差最多 ±4 个月，报告中写“约 X 岁起运”。

## 8. 大运（CAL-YUN）

- 顺逆：**阳年男、阴年女顺排；阴年男、阳年女逆排**。阴阳看年柱天干（甲丙戊庚壬为阳）。注意年柱以立春为界。
- 大运干支：从月柱开始，顺排取下一个干支，逆排取上一个干支，每步 10 年，排 8 步。
- 起运：顺排数出生到**下一个节**的时间，逆排数到**上一个节**的时间（都用绝对时刻），按“3 天 = 1 年”折算：
  `1 天 = 4 个月；1 小时 = 5 天；1 分钟 = 2 小时`（按分钟计，对应 lunar 库 `getYun(gender, 2)`）。
- 起运日期 = 出生日期 + 折算出的年月日时；第 n 步大运开始年份 = 起运日期所在公历年 + 10×(n−1)。
- 年龄对外一律用**周岁**（起运年 − 出生年，按生日是否已过修正），避免“虚岁”误会；内部可保留虚岁字段。
- 流年：流年干支也以立春换年。报告里“2027 年”指 2027-02-04 前后立春起的丁未年，逐年卡片要写清“2027 丁未年（2027 年立春起）”。

## 9. 输出与校验要求

- 每个排盘结果必须带：`input_echo`（原样回显输入）、`clock_to_utc`、`true_solar_time`（若有）、`jieqi_prev`/`jieqi_next`（名称 + 精确时刻）、`rules_hit`（CAL 编号列表）。
- 每个排盘结果还必须带：`tst_status`（"已校正" / "未校正"）、`alt.zi_huanri_day_pillar`（A 派日柱，仅 23:00–23:59 出生时与主结果不同）。
- 测试：rules/cases.json 所有案例四柱 100% 一致；另加“随机 1,000 个时刻与 lunar 库（显式 setSect(2)）比对”的属性测试，其中至少 100 个时刻落在 23:00–23:59。
- 已知会让人出错的地方（写给开发）：
  1. 本项目要 sect=2（晚子时日柱不换日、时干按次日起），必须显式 setSect(2)，并用 C05 测试锁定；不要依赖库默认值；
  2. 月柱、年柱不要用“日期”判断，要用时刻（交节当天上下午可能不同）；
  3. 真太阳时不参与节气比较；
  4. 时区用 tz 库，别手写 +8（夏令时）。

读取 CLAUDE.md、docs/PRD.md 和 rules/ 目录，输出 docs/ARCHITECTURE.md，包括：
- 技术栈及选择理由（优先：简单、成熟、便宜、一个人能维护；倾向 Next.js + TypeScript 全栈 + 一个托管数据库）
- 排盘库选型：调研现成的开源历法/八字库（如 lunar-javascript 等），比较准确性、维护情况、许可证，并说明怎么用 rules/cases.json 验证它
- 模块划分：排盘引擎（纯函数）/ 规则引擎 / 报告拼装（按 rules/texts/ 素材库确定性拼装，不调用大模型）/ 支付 / 订单存储 / 前端
- 数据模型：服务器只存订单（含出生信息的哈希指纹），不存出生信息和报告；报告链接自带编码后的出生信息，打开时校验订单后现算
- 支付方案：比较微信支付、支付宝、聚合支付等对个人 / 个体户的开通条件和费率，列出需要用户去办的手续
- 素材库与拼装引擎：素材格式、选取与兜底、覆盖率测试；预留默认关闭的大模型润色接口
- 部署方案和每月成本估算
- 隐私：出生信息不落库、不进日志，链接中出生信息的处理方式

最后把开发拆成 docs/TASKS.md：每个任务半天内能完成，写明依赖关系和验收方式，排盘引擎和测试排在最前面。
完成后停下，向用户汇报关键选择和需要他办的事（比如支付开通、备案）。

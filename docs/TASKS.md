# TASKS v0.1 —— 开发任务拆分

> 依据：docs/ARCHITECTURE.md v0.1、docs/PRD.md v0.3。
> 规则：每个任务半天内完成；dev agent 每次只做一个任务，完成后跑全部测试、单独 git commit、在此打勾。
> 标记：**【rules】** = 以 rules/ 最终版本为准（rules/ 未定稿时先按接口实现 + 用占位数据测试，定稿后补齐）；**【UI】** = 以 docs/UI.md 为准（若已产出）；**【需你】** = 依赖你办好的外部事项。
> 排盘引擎和测试排在最前面；支付真实联调放在最后，之前全部用 mock 渠道。

## 阶段总览

| 阶段 | 任务 | 内容 |
|---|---|---|
| A 脚手架 | T01–T02 | 项目初始化、测试与 CI 基础 |
| B 排盘引擎 | T03–T11 | 四柱、节气、农历、时区 / 真太阳时、藏干十神、大运流年、三柱模式、对照测试 |
| C 规则引擎 | T12–T17 | 规则框架、五行力量、旺衰、喜用神、案例一致率、性格模板 |
| D 免费流程 | T18–T22 | 数据库、排盘 API、首页、免费结果页、免责 / 隐私页 |
| E 订单与支付 | T23–T30 | 订单状态机、支付抽象 + mock、微信 JSAPI / Native、支付宝、退款、关单 |
| F 报告生成 | T31–T37 | 大模型客户端、提示词、任务队列、分章生成与重试、校验、失败退款、模型评测 |
| G 报告页 | T38–T43 | 报告页、三张图表、逐年卡片、生成中页面、自助删除 |
| H 隐私与上线准备 | T44–T49 | 加密与脱敏、过期清理、统计、Docker、CI、E2E |

## A 脚手架

- [ ] **T01 项目初始化**
  依赖：无
  内容：Next.js（App Router、TypeScript strict、`output: 'standalone'`）+ Tailwind + ESLint/Prettier；目录按 ARCHITECTURE 第 3 节建空模块；`.env.example`（只列变量名）；确认 `.gitignore` 已含 `.env`。
  验收：`npm run dev` 能打开空首页；`npm run build` 通过；仓库中无任何密钥。

- [ ] **T02 测试基础设施**
  依赖：T01
  内容：Vitest 配置、`npm test`；GitHub Actions 跑 lint + typecheck + test；`tests/fixtures/` 目录约定。
  验收：一个示例测试在本地和 CI 都通过；CI 失败时 PR 显示红叉。

## B 排盘引擎（纯函数，`src/lib/bazi`）

- [ ] **T03 历法适配层 + 四柱**
  依赖：T02
  内容：安装 tyme4ts（锁精确版本）；`calendar-adapter.ts` 封装公历时间 → 年月日时四柱、节气交接时刻；定义内部类型 `Pillar`、`Chart` 初版。库调用只允许出现在此文件。
  验收：10 个手工挑选的已知八字（含立春前后）四柱正确；`grep` 确认其他文件不直接 import tyme4ts。

- [ ] **T04 cases.json 对照测试框架** 【rules】
  依赖：T03
  内容：`cases.json` loader（字段映射到 `BirthInput`，以 cases.json 最终字段为准）；参数化测试：每个案例断言四柱 100% 一致，失败时打印案例 ID 和差异。rules/cases.json 不存在时测试显示 skip 并警告，而不是通过。
  验收：rules/cases.json 中全部案例四柱通过（P0-2）；loader 有单元测试。

- [ ] **T05 节气边界与交叉对照测试**
  依赖：T03
  内容：① 1950–2050 年每个「节」交接前 / 后 1 分钟自动生成用例，断言月柱（立春含年柱）切换；② 抽取香港天文台 / 紫金山天文台公布的若干年份节气时刻作固定数据（文件头注明来源 URL），断言误差 ≤ 1 分钟；③ lunar-javascript 作为 devDependency，随机 1 万个时间点差分对照四柱。
  验收：三类测试全部通过；不一致样例为 0（若有，写入 docs/QUESTIONS.md 停下问用户）。

- [ ] **T06 输入归一化：农历、闰月、非法日期、子时** 【rules】
  依赖：T03
  内容：农历（含闰月）→ 公历；非法日期（如农历无此闰月、2 月 30 日）返回明确错误码；子时（23:00–01:00）归属按 rules/calendar.md 选择早 / 晚子时 provider。
  验收：闰月、子时前后、非法日期各至少 3 个用例通过；错误码有中文提示文案映射。

- [ ] **T07 时区、历史夏令时、真太阳时** 【rules】
  依赖：T06
  内容：中国 1986–1991 年夏令时修正（口径以 rules/calendar.md 为准）；可选真太阳时 = 经度差 × 4 分钟 + 均时差；内置区县经纬度静态表（核实数据来源和许可证，写在文件头）；Chart 中记录「输入时间 / 校正后时间 / 校正项」。
  验收：夏令时起止日前后用例通过；乌鲁木齐、上海等经度差异明显的城市用例通过；校正导致换时柱的边界用例通过。

- [ ] **T08 藏干、十神**
  依赖：T03
  内容：四柱地支藏干（主 / 中 / 余气）、天干与藏干十神；输出放进 Chart。
  验收：cases.json 若含十神 / 藏干字段则全部一致；另有 5 个手工核对用例。

- [ ] **T09 起运、大运、流年** 【rules】
  依赖：T03, T06
  内容：按性别和年干阴阳定顺逆；起运岁数算法按 rules/calendar.md 选 provider；输出 8～10 步大运（起止年份、干支）和「当前年起未来 5 年」流年表（年份、干支、所在大运）。
  验收：cases.json 中带大运的案例全部一致；顺排 / 逆排各 2 个手工用例；流年表年份与干支对应正确。

- [ ] **T10 三柱模式（不知道时辰）**
  依赖：T03, T08, T09
  内容：`hour: null` 时 `hourPillar: null`，藏干十神等相应字段为空；Chart 标记 `hourKnown: false`。
  验收：至少 3 个三柱用例：前三柱与知道时辰时一致、时柱为空、下游不报错。

- [ ] **T11 Chart 输出定稿 + 确定性 / 快照测试**
  依赖：T07, T08, T09, T10
  内容：Chart 用 Zod schema 定义并导出；加入 `engineVersion`；快照测试；同一输入两次结果深度相等；性能测试（单次排盘 < 50ms）。
  验收：全部排盘测试通过；`engineVersion` 未变时快照不变。

## C 规则引擎（纯函数，`src/lib/rules`）—— 全部 【rules】

- [ ] **T12 规则框架 + 规则覆盖测试**

  验收：覆盖测试能在故意删掉一个实现时变红；rules/ 未定稿时用 fixture md 验证机制。

- [ ] **T13 五行力量计算**
  依赖：T12
  内容：按 rules/strength.md 的权重（天干、藏干主次气、月令系数等）计算五行分数；数值表放 `lib/rules/config/*.json` 并注明来源章节。
  验收：cases.json 中带五行分数 / 排序的案例一致；每个分数可追溯到触发规则。

- [ ] **T14 日主旺衰**
  依赖：T13
  内容：按 rules/strength.md 输出旺衰等级 + 分数 + 触发规则列表（编号和依据文字）。
  验收：每个结论都带至少一条 RuleHit；单元测试覆盖每条旺衰规则。

- [ ] **T15 喜用神 / 忌神**
  依赖：T14
  内容：按 rules/yongshen.md 输出用神、喜神、忌神 + 触发规则。三柱模式按规则处理。
  验收：同上；三柱模式有用例。

- [ ] **T16 案例结论一致率报告**
  依赖：T15, T04
  内容：对 cases.json 中有人工标注的案例比较旺衰、喜用结论；一致率 ≥ 90% 断言；生成不一致清单（案例 ID、我方结论、标注结论、触发规则）输出到测试日志。
  验收：一致率 ≥ 90%（P0-3）；不一致清单可读，交给命理专家逐条确认。

- [ ] **T17 一句话性格画像（模板）**
  依赖：T15
  内容：按规则（日主、旺衰等）选模板拼句，不调大模型；模板文件纳入版本管理；关键词检测确保无恐吓 / 断言用语。
  验收：同输入同输出；所有模板通过敏感词检测。

## F 报告生成

- [ ] **T31 大模型客户端**
  依赖：T02
  内容：`lib/llm`：基于 `openai` 包的 OpenAI 兼容客户端，主 / 备供应商由环境变量配置；超时 40 秒；返回 token 用量并按配置单价换算花费（厘）。
  验收：用本地 mock server 测试成功、超时、5xx、非法 JSON 四种情况。

- [ ] **T32 提示词文件与章节输出 schema** 【rules】
  依赖：T31, T15
  内容：`prompts/system.md`、`prompts/sections/*.md`（章节按 rules/report-sections.md）、`prompts/banned-words.txt`；每章 Zod 输出 schema；提示词版本号。
  验收：每个章节都有 prompt + schema；章节清单与 rules/report-sections.md 一致（测试比对章节编号 / 标题）。

- [ ] **T33 任务队列 worker**
  依赖：T18, T24
  内容：`worker/` 进程：`FOR UPDATE SKIP LOCKED` 取 Job、失败退避重试、优雅退出；任务类型：生成报告、退款、关单、清理。
  验收：并发两个 worker 不会重复处理同一任务（集成测试）。

- [ ] **T34 分章并行生成 + 重试 / 切换备用模型**
  依赖：T32, T33
  内容：读取 Chart + Analysis 组装每章输入；并行调用；每章最多重试 3 次（第 2 次起用备用模型）；整份硬上限 120 秒；已成功章节不重跑；记录 GenerationAttempt 和总花费。
  验收：mock LLM 下：全成功、单章失败后恢复、全部失败三种场景测试通过；同一订单重复入队不会再次调用模型。

- [ ] **T35 报告校验（一致性 + 字数 + 敏感词）**
  依赖：T34
  内容：抽取正文中的年份 / 干支与 Chart 流年、大运表比对；单章和全文字数区间（全文 5,000～8,000 字）；敏感词检测；不通过视为该章失败触发重试。
  验收：构造的错误干支、超字数、含敏感词样例都能被拦截；合法样例通过。

- [ ] **T36 最终失败自动退款与提示**
  依赖：T34, T29
  内容：报告 FAILED → 入队 REFUND → 订单 refunding → refunded；前端显示「生成失败，已原路退款」及联系方式。
  验收：mock 场景下从失败到退款全链路测试通过。

- [ ] **T37 模型评测脚本（决定最终模型）** 【需你：API Key 和少量预算】
  依赖：T35
  内容：脚本对 5 个案例分别用 2～3 个候选模型生成完整报告，输出耗时、token、成本、校验结果，并导出 Markdown 供盲评。运行前先问用户（会产生费用，预计 < ¥20）。
  验收：产出评测表；单份成本 < ¥2、生成 < 60 秒的模型至少一个；由用户拍板写入 `.env.example` 默认值说明。

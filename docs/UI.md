## 1. 设计原则

1. **像书，不像聊天记录。** 报告是一页一页排好的版面：有封面、目录、章节号、图表编号、页脚；正文是段落，不是对话气泡；不出现「AI」「助手」字样。
2. **克制即专业。** 每屏只有一个视觉重点，颜色最多三种（墨、纸、朱砂），五行色只用在五行字、五行图上，而且都是低饱和色。
3. **依据看得见。** 每条结论后面紧跟一行小字「据 ……」（rules/ 的依据模板），读者能看出结论从哪来，这是和普通 AI 拉开差距的主要视觉标志。
4. **价格诚实。** 价格只出现在按钮和确认面板上，不用划线价、倒计时、「xx 人已测」、角标「限时」。付款前就告诉用户「链接要自己保存」。
5. **不吓人。** 不用红色表示「凶」；大运、流年的「宜稳守」用灰蓝，「向好」用浅朱砂；不出现警示图标。
6. **手机先行。** 所有页面先按 375×667 设计，可点区域至少 40×40 px，正文 16 px 起，没有横向滚动。

- **不加载任何第三方字体**（ARCHITECTURE 2.2 和 6.4 的 CSP 要求）。macOS、Windows 有宋体和楷体；iOS、安卓上中文衬线字体是否默认可用**未核实**。

#### 自托管标题字体（2026-10-29 用户确认）

- **字体**：思源宋体（Source Han Serif SC / Noto Serif SC），SIL Open Font License 1.1，可商用、可子集化、可随网站分发；许可证文本随字体文件一起放进仓库。只收 SemiBold 一个字重。
- **子集字表来源**：只收**固定字**，由构建脚本从以下来源自动汇总、去重，生成 `apps/web/public/fonts/charset.txt`（提交进仓库）：
  1. 前端代码中的固定界面文案：章节标题、模块标题、封面「命书」、状态页标题、按钮文字、站名与印章字；
  2. 命理固定字：十天干、十二地支、十神（比肩……正印）、十神组读者名（比劫、印星、食伤、财星、官杀）、五行、旺衰等级、格局名（从财格等）、档位名（顺势期……宜保守、打基础）、四个吉神名、「年月日时柱」「日主」「男命女命」「第〇一二……八章」「图一二三」等；
  3. 数字 0–9 和常用标点（· ， 。 「 」 （ ） — ～ % ¥ /）。
  预计几百个字，体积目标 < 100 KB woff2（未实测，以构建产物为准）。**素材库正文不进子集**：正文字数多、内容会变，仍用系统字体。
- **加载**：woff2 文件放在本站 `/fonts/` 下，同源加载，文件名带内容哈希、长期缓存；只在 `@font-face` 里声明 `font-family: "ZM Serif"`，并把 `unicode-range` 限定在字表范围内；`font-display: swap`；首页不预加载（首页标题少，用系统字体也能接受），结果页和报告页在 `<head>` 里 `preload`。CSP 需包含 `font-src 'self'`。
- **回退**：`--serif-title: "ZM Serif", var(--serif)`。字体没加载到或字表外的字，按 `--serif` 依次退到系统宋体，再退到黑体。版式层级仍靠字号、字重、颜色、留白和印章，纯黑体下也要成立（开发验收时用安卓微信截图检查）。
- **长图**：生成长图前等待 `document.fonts.ready`，保证截图字形一致。
- **校验**：构建时加一个检查，扫描固定文案与命理固定字是否都在字表里，缺字就失败；改了界面文案后重新生成子集。
- 原型（`design/`）不带字体文件，仍用系统字体示意。
- 数字用 `font-variant-numeric: tabular-nums`（百分比、年份对齐）。

### 2.3 间距、圆角、线

- 间距基数 4 px；页面左右边距 16–18 px；模块间距 12 px；章节之间 30 px。
- 圆角：按钮和输入框 4 px，卡片 6 px，印章 3 px，底部面板 10–12 px。不用大圆角和胶囊形。
- 线：1 px `line`。封面和付费引导框用「外细墨线 + 内细淡线」双框，模仿书籍版框；章节标题下用「粗细双横线」。
- 阴影：只在浮层面板上使用，正文区域不用阴影。

### 2.4 印章

- 一枚朱砂方印，文字竖排「知命」（**站名待定**，改名后替换）。只出现在三处：页头 logo、报告封面右下角（轻微旋转 −4°）、报告结尾。
- 不在其他地方滥用「印章」效果（例如结论加盖「吉」字印），避免往玄学风滑。

### 2.5 纸纹

页面底色叠一层 `feTurbulence` 噪点（内联 data URI SVG，不透明度约 7%）。要求：
- 只用在 `body` 底色上，卡片不加；
- 长图生成如果不支持 data URI 背景，就退回纯色 `paper`，不影响阅读；
- CSP 需允许 `img-src data:`（或改为构建时生成的同源小图）。

### 2.6 明确不用的元素

八卦图、太极图、星空 / 紫色 / 蓝紫渐变、发光描边、烫金纹理、龙凤祥云、罗盘、旋转动画、塔罗风卡背、emoji、「大师」头像、「吉 / 凶」大字、红色警示图标、倒计时、划线价、销量 / 人数、悬浮客服按钮。

### 4.2 字段规则

| 字段 | 控件 | 规则 |
|---|---|---|
| 历法 | 分段按钮，默认公历 | 切到农历时，月份变成「正月……腊月」，该年有闰月时插入「闰X月」（calendar.md CAL-INPUT）；日变成「初一……三十」 |
| 年 | 原生 `<select>`，**倒序**（今年 → 1930），首项是占位「年」 | 原生选择器在手机上体验最好；倒序让主力用户（1986–2008 年出生）少滑动 |
| 月 / 日 | 原生 `<select>` | 非法日期（公历 2 月 30 日、农历小月三十、不存在的闰月）在提交时就地标红提示，不弹窗 |
| 时 / 分 | 两个原生 `<select>`：「00 时 · 子（早子）」……「23 时 · 子（晚子）」；「00 分」……「59 分」 | 时辰名只作辅助显示，提交的是精确时分（交节、真太阳时都需要分钟） |
| 不知道时辰 | 复选框 | 勾选后时分两个下拉框变灰禁用，并提示「不知道时辰也能排：只排年、月、日三柱，部分结论会标注可信度」 |
| 性别 | 分段按钮，**无默认值** | 没选就提交时，就地提示「请选择性别」 |
| 出生地 | 按钮 → 底部面板（可搜索；省 → 市 → 区县；最后一组是「海外 / 港澳台」） | 选中后按钮变成实线框并显示「清除」；新疆的城市旁注「请填北京时间」（calendar.md §5） |

### 4.3 情境提示（灰字，出现在对应字段下方，不弹窗）

| 触发 | 文案 |
|---|---|
| 选 23 时 | 23:00–23:59 为晚子时：日柱仍算当天（本站采用早晚子时派）。 |
| 选 0 时 | 00:00–00:59 为早子时：日柱算当天（即已过午夜的这一天）。 |
| 公历 1986–1991 年 4–9 月 | 这段时间中国实行夏令时。请照出生证上的钟表时间填写，我们会自动换算。 |
| 农历且该年有闰月 | 农历 X 年有闰 Y 月，如出生在闰月请选「闰 Y 月」。 |
| 夏令时不存在的时刻 | 提交后显示状态页画板 5「这个时间无法排盘」（错误码映射，不回显输入值） |

- **交节日 + 不知道时辰的「之前 / 之后 / 不确定」选择不放在首页**：首页不知道哪天交节，由结果页的四柱模块处理（§5.3）。这和 ARCHITECTURE 6.1 的流程一致，首页也因此保持一屏。
- 首页不保存任何输入到服务器。提交后生成载荷，跳到 `/result#…`。

## 5. 免费结果页（`result.html`）

### 5.1 结构

1. 顶栏：印章 + 「八字结果」，右侧「重新输入」。
2. 输入回显条：「公历 1981年10月27日 11:28 · 男 · 未选出生地」+「修改」。
3. 模块一 **四柱八字**：4 列（年、月、日、时）× 5 行（十神 / 天干 / 地支 / 藏干 + 藏干十神）。日柱整列浅朱砂底，十神位置写「日主」。干支字按五行着色。
   下方灰字（calendar.md §4，原文照用）：
   - 未校正：「时辰按北京时间排定，未做真太阳时校正。如出生地离东经 120° 较远，时柱可能不同，可补充出生地重新排盘。」其中「补充出生地重新排盘」是链接，回到首页并保留已填内容。
   - 离时辰边界不足 30 分钟时追加：「你的出生时间接近时辰交界，补充出生地后时柱可能变化。」（C11 的 11:28 离 11:00 只有 28 分钟，所以原型里显示了这句。）
   - 已校正：「北京时间 11:28 → 真太阳时 11:50（上海市黄浦区：经度修正 +6 分，均时差 +16 分）。时辰仍为午时。」
4. 模块二 **五行强弱**：横向条形图，5 行，顺序固定为木火土金水。数据用 `power_display_pct`（含日主，strength.md §6）。日主所在一行加朱砂细框，并标注「日主」。图下一句：「帮扶你的力量（同党）占 68%，消耗你的力量（异党）占 32%。」
5. 模块三 **日主旺衰**：左边是朱砂细框里的等级大字（「身旺」），右边一句话：「戊土生于戌月，得令，帮扶力量占 68%，属身旺。」下方是四档刻度（身弱 / 中和偏弱 / 中和偏旺 / 身旺），当前档高亮；再下面是三个「得」的小标签（得令、得地、得势），命中的标实心点。从格、专旺不放在四档刻度里：刻度换成单个标签「从财格」等，句子照 R-FREE 模板生成。
6. 模块四 **喜用神与忌神**：两个盒子，左边「对你有利」（金带「用」角标，水带「喜」角标），右边「需要节制」（土、火）。下面是 R-FREE 原句：「对你有利的五行：金（主）、水；需要节制的五行：土、火。」免费页**不显示闲神**。

## 8. 图表规范（MVP 3 张，手写 SVG）

通用要求：SVG 内联渲染，`viewBox` 宽 340，按容器宽度缩放；所有颜色块旁边都有文字标签；用 `role="img"` + `aria-label` 写一句话摘要；不用动画（长图截图要稳定）；不依赖 hover。

### 图一 五行力量（第一章）

- 横向条形图：5 行，顺序固定木火土金水。每行依次是「五行字 + 十神组小字（官杀 / 印星 / 比劫 / 食伤 / 财星）」、条形、百分比、角色标签（用 = 朱砂实底；喜 = 朱砂框；忌 = 灰框；闲 = 灰字）。
- 数据用 `power_display_pct`（含日主），日主一行加朱砂细框。
- 图注（固定）：「红框为日主所在五行。图中占比包含日主本身；正文中的百分比不含日主，所以比劫在正文中为 {gods.比劫_pct}%。同党（帮扶你的力量）占 x%，异党（消耗你的力量）占 y%。」——这句用来解决「图上土 45%、正文比劫 40%」对不上的问题（strength.md §6 两套口径）。
- **为什么不用雷达图**：某一行为 0 时（C11 的水 = 0%）雷达图会塌成怪异的形状；手机上 5 个角的数值难读；雷达图本身也带「测评软件」的气质。条形图可读、截图清晰，和免费页保持一致（免费页按 R-FREE 必须用柱状图）。已确认（2026-10-29），见 §13 U2。

### 图二 大运时间轴（第五章）

- 8 列，每列一步大运。顶部是干支（宋体），中间是以基线为 0 的上下柱（高度 = 分数 × 50 px，上正下负），柱色 = 档位色，柱旁写档位文字，底部是起运周岁和起始年份。
- ±0.4、±1.2 处画虚线，对应档位分界（R-YUN-SCORE）。
- 已过去的大运透明度 45%；当前大运整列铺浅朱砂底，柱子加朱砂描边，顶部标「当前」。
- 图下是档位图例，再下面是 8 行列表（年龄与年份 / 干支 / 天干十神 / 档位），当前一行高亮。图负责看趋势，列表负责查具体数据；列表在长图里也清楚。

## 9. 保存为长图（PRD P0-9）

### 9.1 版式

- 固定 **600 CSS px** 宽，按 2 倍像素渲染（1200 px 宽）；左右内边距 28 px；底色用纯色 `paper`。
- **分 3 张**（2026-10-29 用户确认，保留封面出生日期），在章节边界切开：① 封面、目录、第〇至第二章；② 第三至第五章；③ 第六至第八章。每张单独生成。
  理由：iOS 和微信内核的 canvas 有面积上限（具体数值**未核实**，ARCHITECTURE 13 节列为风险），整份报告在 600 px 宽下预计高 15,000 px 以上，一张图很可能超限，而且相册里一张超长图也很难翻看。实际切点由预研结果定：单张高度的上限取预研测得的安全值。
- 每张都有**页眉**「命书 · 戊土日主 · 男命」/「第 n / 3 张」和**页脚**「长图由你的手机本地生成，服务器不保存 · 生成于 YYYY-MM-DD · 图中含出生信息，请勿公开发布 · 传统文化参考，不构成专业建议」。
- 长图中**去掉**：保存提示条、底部操作条、目录里的链接样式、所有按钮、原型标记。**保留**：封面上的出生信息（用户自己留存需要；页脚已提示勿公开）。
- 原型中勾选「长图版式预览」即可看到效果，朱砂虚线是分张位置。

### 9.2 交互

1. 点「保存长图」→ 全屏深色浮层「正在生成长图…… 在你的手机上生成，不经过服务器，约需几秒。」
2. 生成完成 → 浮层标题改为「长按图片，保存到相册」，3 张缩略图可以左右滑动；每张都是真实的 `<img>`，微信内长按就能保存（ARCHITECTURE 2.2）。
3. 电脑端：每张图下面有「下载」按钮；另外提示「也可以用浏览器『打印 → 存为 PDF』」。打印样式已在原型中隐藏操作条（`@media print`）。
4. 生成失败：浮层显示「生成失败，可以先复制链接保存」+「重试」+「复制链接」。

## 11. 兼容与实现提示（给前端）

- **微信内置浏览器**：页面要处理 `env(safe-area-inset-*)`；高度用 `100dvh`，并保留 `100vh` 作为兜底；底部固定条在 iOS 键盘弹出时会被顶起，首页不放固定底栏，按钮放在文档流里；出生地面板里的搜索框不自动聚焦。
- **原生 select**：iOS 和安卓微信里原生选择器最稳定，不要换成自绘的滚轮组件。
- **CSP**（ARCHITECTURE 6.4）：生产环境不允许内联脚本，原型中的 `<script>` 只是演示。SVG 的 `style` 属性尽量改成 class 或 SVG 属性；纸纹用 data URI 时需要 `img-src 'self' data:`。
- **不引入第三方脚本**：没有统计、客服、字体 CDN。原型已经满足这一点。
- **图表组件**：五行图可以用 HTML 条形（原型做法），也可以用 SVG，两种都能截图；大运和流年图用 SVG。所有数据直接来自报告 JSON，前端不做任何计算。
- **长图**：生成前给 `body` 加 `li` 类（原型中的写法），切换到长图版式后再截图，截完恢复。
- **无障碍**：干支着色只是辅助，文字本身是完整的；图表有 `aria-label`；按钮都是真正的 `<button>` 或 `<a>`；对比度见 §2.1。
- **打印**：`@media print` 隐藏操作条和提示条，电脑端可以「打印 → 存为 PDF」作为 PDF 导出（P1）之前的替代。
